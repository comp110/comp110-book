# Agent Guide

This is a small Zensical static documentation site managed with `uv`. Source content lives in `docs/`; the generated site is written to `site/`.

## Quick Start

- Install/sync dependencies: `uv sync` or `make sync`
- Build the site: `make build`
- Serve locally: `make serve`
- Run tests: `uv run pytest`

The preview server is configured in `zensical.toml` as `0.0.0.0:8000`.

## Project Map

- `zensical.toml`: site configuration, navigation, Markdown extensions, and registered assets.
- `docs/`: Markdown pages plus browser assets.
- `docs/javascripts/python-runner.js`: Pyodide/CodeMirror runner for `python_runner` fences.
- `docs/stylesheets/python-runner.css`: runner and editor styling.
- `markdown_plugins/pyodide_fence.py`: custom SuperFences formatter that renders runnable Python blocks.
- `tests/test_python_runner.py`: Playwright regression test for editable/runnable Python examples.
- `site/`: generated build output; avoid editing it directly unless the user specifically asks.

## Runnable Python Blocks

Runnable examples use fenced Markdown blocks named `python_runner`. The custom fence formatter emits a `.python-runner` widget with a hidden `<pre>` fallback, a run button, an output area, and source text for CodeMirror.

The browser runner currently:

- Loads Pyodide from jsDelivr.
- Loads CodeMirror modules from esm.sh.
- Adds Python syntax highlighting through `@codemirror/lang-python` and `@lezer/highlight`.
- Runs checks in this order: syntax check, `mypy` type check, then execution.
- Installs browser-side type-check dependencies once with Pyodide/micropip: `micropip`, `typing-extensions`, `mypy`, `mypy-extensions`, and `pathspec`.
- Surfaces syntax, type, and runtime failures in the output pane and as CodeMirror diagnostic underlines.

When changing the runner, keep the output pane behavior and diagnostic CSS classes in sync:

- `.python-runner__diagnostic`
- `.python-runner__diagnostic--error`
- `.python-runner__diagnostic--warning`
- `.python-runner__diagnostic--info`

## Testing Notes

`uv run pytest` builds the site and runs the Playwright browser regression test. The test needs browser access to CDN-hosted Pyodide/CodeMirror assets and may take longer on a cold cache.

For changes limited to Markdown content, `make build` is usually enough. For changes to `docs/javascripts/python-runner.js`, `docs/stylesheets/python-runner.css`, `markdown_plugins/pyodide_fence.py`, or `zensical.toml`, run `uv run pytest`.

## Editing Guidelines

- Prefer editing source files in `docs/`, `markdown_plugins/`, and config files rather than generated files in `site/`.
- Keep JavaScript browser code dependency-light; current third-party browser modules are loaded dynamically from CDNs.
- Preserve the static fallback `<pre class="python-runner__code">` generated by the fence formatter so examples remain visible if CodeMirror fails to load.
- If adding new assets, register them through `zensical.toml` using `extra_css` or `extra_javascript`.
- Keep test coverage focused on the browser behavior users actually touch: editor creation, editing, running, output display, and diagnostics.
